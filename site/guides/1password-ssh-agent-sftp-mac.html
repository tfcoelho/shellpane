Use the 1Password SSH agent with an SFTP app on your Mac

Checked against 1Password's developer docs on 13 October 2026.

Short answer: tell ssh where the agent is in ~/.ssh/config, not only in your shell profile. Any app built on OpenSSH then finds your 1Password keys, however it was opened.

Host *
  IdentityAgent "~/Library/Group Containers/2BUA8C4S2C.com.1password/t/agent.sock"

Why it works in Terminal and not in your app

A common setup puts export SSH_AUTH_SOCK=… for the 1Password agent in ~/.zshrc. Terminal runs your shell, so ssh in Terminal sees that variable and finds your keys.

An app you open from the Dock or Finder doesn't start from your shell. It gets the environment macOS's launchd gives every app, where SSH_AUTH_SOCK points at macOS's own ssh-agent, which doesn't hold your 1Password keys. So the app asks for a key file, or the server refuses the login.

IdentityAgent in ~/.ssh/config fixes it at the source: ssh reads the file every time it connects, whoever started it.

1. Check the agent works in Terminal

List the keys the 1Password agent offers:

SSH_AUTH_SOCK=~/Library/Group\ Containers/2BUA8C4S2C.com.1password/t/agent.sock ssh-add -l

If that lists your keys, the agent is running. If it says it can't connect, turn on the SSH agent in 1Password's settings (Developer section) and try again.

2. Add IdentityAgent to ~/.ssh/config

Add the block from the short answer to ~/.ssh/config, for all hosts as shown or inside a single Host block. The quotes matter, because the path has a space in it.

To avoid the space altogether, 1Password suggests a shorter link:

mkdir -p ~/.1password && ln -s ~/Library/Group\ Containers/2BUA8C4S2C.com.1password/t/agent.sock ~/.1password/agent.sock

Then use IdentityAgent ~/.1password/agent.sock.

Check what ssh will actually use for a host:

ssh -G yourserver | grep -i identityagent

3. Keys in a shared or work vault

With no configuration, the agent offers SSH keys from your default Personal, Private or Employee vault. Keys in other vaults, such as a team's shared vault, aren't offered until you list them in ~/.config/1Password/ssh/agent.toml:

[[ssh-keys]]
vault = "Private"

[[ssh-keys]]
vault = "Work"

The default only applies when the file doesn't exist, so list your own vault in it too.

4. "Too many authentication failures"

OpenSSH servers allow six authentication attempts by default. With many keys in 1Password, the agent can offer six wrong ones before the right one. Point each host at its key, using the public key downloaded from 1Password:

Host yourserver
  IdentityFile ~/.ssh/yourserver.pub
  IdentitiesOnly yes

1Password notes that some SSH clients don't accept a public key in IdentityFile. OpenSSH does.

If your app still doesn't find the keys

Some file transfer apps don't use OpenSSH. They have their own SSH library, and may ignore IdentityAgent, parts of ~/.ssh/config, or public keys in IdentityFile. Check the app's documentation for an agent or socket setting. If there isn't one, the config above won't reach it.
